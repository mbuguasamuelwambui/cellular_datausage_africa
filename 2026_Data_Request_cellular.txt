================================================================================
DATA ACQUISITION REQUEST: RAW CELLULAR NETWORK TELEMETRY (2015 vs 2026)
Prepared by: Data Science & Artificial Intelligence Lab (DSAIL)
Target Timeline: Two weeks of network telemetry from 2026
================================================================================

1. RESEARCH BACKGROUND & OBJECTIVE
--------------------------------------------------------------------------------
Research laboratory was conducted on a longitudinal comparative study between a 2015 baseline cellular trace (55TB) and a modern 2026 dataset. We aim to quantify the infrastructural 
improvements made over the last decade, specifically measuring the impact of 4G/5G upgrades, CDN localization, and modern Active Queue Management (AQM) on protocol efficiency.

To execute our deep-extraction mathematical models, we require RAW, unaggregated network telemetry. We do not want pre-binned data or histograms; we need the raw, event-level flow records 
to independently calculate our own distributions.

2. PRIVACY, COMPLIANCE, AND SECURITY GUARANTEE
--------------------------------------------------------------------------------
Because we are requesting raw flow logs, we mandate the strictest adherence to data protection laws:
- NO USER PAYLOADS: We do not require Deep Packet Inspection (DPI) of user content. We only require L3/L4 transport headers.
- STRICT ANONYMIZATION: All subscriber identifiers (IMSI, MSISDN, IMEI) MUST be one-way cryptographically hashed or replaced with ephemeral random integers before export.
- NO CLEAR-TEXT URLs: Domain requests should be truncated to the Top-Level/Second-Level Domain (e.g., youtube.com) rather than full URIs.

3. CAPTURE PARAMETERS
--------------------------------------------------------------------------------
- Duration: One continuous 14-day period.
- Scale: A representative sample (e.g., ~200,000 active subscribers) spanning urban and rural nodes.
- Tap Point: Core Network Interfaces (SGW/PGW for 4G, or UPF for 5G).

4. REQUIRED RAW DATA SCHEMAS
--------------------------------------------------------------------------------
We request that your data engineering teams to support us to export raw, unaggregated flow and event logs mapping to the following functional requirements:

GROUP A: RAW FLOW DATA RECORDS (FDR / IPFIX / NetFlow)
Purpose: To measure asymmetric load balancing, per-flow throughput, and exact volume per Radio Access Technology (RAT).
Required Schema (Per-Flow Row):
- Timestamp (Start and End)
- Hashed Subscriber ID
- Radio Access Technology (2G/3G/4G/5G)
- Transport Protocol (TCP / UDP / QUIC)
- Total Bytes Uplink / Total Bytes Downlink

GROUP B: RAW TRANSPORT LAYER QoS LOGS
Purpose: To calculate exact Cellular Bufferbloat degradation, TCP/QUIC packet loss, and latency reductions.
Required Schema (Per-Flow Row):
- Flow ID (to join with Group A)
- Exact Round Trip Time (RTT) in milliseconds for the SYN/Setup phase
- Exact average RTT for the active payload phase
- Raw count of Retransmissions, Duplicate ACKs, and Out-of-Order packets for that specific flow

GROUP C: RAW DNS QUERY LOGS
Purpose: To measure the reduction of the "Invisible DNS Tax" and assess modern application dominance.
Required Schema (Per-Query Row):
- Timestamp
- Hashed Subscriber ID
- Requested Domain (Truncated to SLD/TLD)
- Resolver IP utilized (e.g., ISP Default vs. Google 8.8.8.8)
- Exact Query Resolution Latency in milliseconds

GROUP D: RAW EDGE ROUTING & DESTINATION LOGS
Purpose: To quantify the speed improvements gained by routing traffic to local East African CDNs.
Required Schema (Per-Flow Row):
- Flow ID
- Anonymized Destination IP (Truncated to /24 subnet)
- Traceroute/penultimate hop IP (if available from core routers)

GROUP E: RAW CORE NETWORK SIGNALLING (CONTROL PLANE)
Purpose: To measure how modern networks handle the continuous "keep-alive" signaling overhead generated by smartphones.
Required Schema (Per-Event Row):
- Timestamp (Millisecond precision)
- Hashed Subscriber ID
- Signalling Message Type (e.g., GTP-C Create/Update/Delete Session, or 5G SMF equivalents)
- Note: If a 14-day capture of raw control plane signaling exceeds export capabilities, a focused 24-hour peak-time capture is highly acceptable.

5. DATA DELIVERY FORMAT
--------------------------------------------------------------------------------
Given the anticipated multi-terabyte scale of these raw logs, we expect delivery in compressed Big Data formats (e.g., Apache Parquet, Snappy-compressed CSVs, or HDF5). We can provision a secure, 
encrypted cloud bucket for direct pipeline transfer, or coordinate the handover of physical encrypted enterprise drives.
